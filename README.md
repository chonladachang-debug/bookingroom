## 1. รายการไฟล์ในชุดข้อมูล

## 2. รูปแบบของไฟล์

ทุกไฟล์เป็นข้อความธรรมดา (plain text) โดย **บรรทัดแรกคือจำนวนข้อมูล** จากนั้นจึงเป็นค่าข้อมูลคั่นด้วยช่องว่างหรือขึ้นบรรทัดใหม่

```
1000
4661 8235 1207 9998 ...
...
```

ไฟล์ `targets_*.txt` ใช้รูปแบบเดียวกัน บรรทัดแรกคือจำนวนค่าที่ต้องค้นหา (เท่ากับ 10 ทุกไฟล์)

ข้อมูลทุกค่าเป็น **จำนวนเต็มบวกที่ไม่ซ้ำกัน** อยู่ในช่วง 1 ถึง 10n จึงไม่ต้องกังวลเรื่องค่าซ้ำหรือค่าติดลบ

## 3. ค่าที่ใช้ค้นหา 10 ค่า เลือกมาอย่างไร

ค่าทั้ง 10 ถูกเลือกมาให้ครอบคลุมทุกกรณีที่ส่งผลต่อเวลาในการค้นหา จึงไม่ควรใช้ค่าอื่นแทน

| ลำดับ | ประเภทของค่า | ทดสอบอะไร |
|---|---|---|
| 1 | ค่าที่น้อยที่สุดในชุด | กรณีที่อยู่ต้นสุดของข้อมูลที่เรียงแล้ว |
| 2 | ค่าที่มากที่สุดในชุด | กรณีที่อยู่ท้ายสุด (Worst case ของ Sequential บนข้อมูลเรียง) |
| 3 | ค่ากลางของชุดข้อมูล | Best case ของ Binary Search — เจอในรอบแรก |
| 4–5 | ค่าที่ควอไทล์ที่ 1 และ 3 | กรณีทั่วไป |
| 6–7 | ตัวแรกและตัวสุดท้ายของไฟล์ที่ยังไม่เรียง | Best/Worst case ของ Sequential Search |
| 8–10 | **ค่าที่ไม่มีอยู่ในชุดข้อมูล** | กรณีค้นแล้วไม่พบ ซึ่งเป็น Worst case ของทุกอัลกอริทึม |

**สรุปแต่ละขนาด: พบ 7 ค่า และไม่พบ 3 ค่า** — ใช้ตรวจสอบความถูกต้องของโปรแกรมได้ทันที หากกลุ่มใดรายงานว่าพบครบทั้ง 10 ค่า แสดงว่าโปรแกรมมีข้อผิดพลาด

## 4. กติกาการใช้งาน

1. **กลุ่มที่ใช้ Binary Search, BST หรือ AVL Tree** ให้ใช้ไฟล์ `data_*_sorted.txt` หรือจะอ่านไฟล์ที่ยังไม่เรียงแล้วเรียงเองก็ได้ แต่ **ห้ามนับเวลาการเรียงลำดับรวมเข้าไปในเวลาการค้นหา** เพราะเป็นขั้นตอนเตรียมข้อมูล
2. **กลุ่มที่ใช้ Sequential Search หรือ Hash Table** ให้ใช้ไฟล์ `data_*.txt` ที่ยังไม่เรียง
3. จับเวลาเฉพาะส่วนของอัลกอริทึมการค้นหาเท่านั้น ไม่รวมการอ่านไฟล์ การเรียงข้อมูล และการแสดงผลทางจอภาพ
4. ใช้ค่า `REPEAT` เดียวกันตลอดทุกการทดลองของกลุ่ม และระบุค่าที่ใช้ในรายงาน
5. รันวัดขนาดละ 5 ครั้ง ตัดค่าสูงสุดและต่ำสุดออก แล้วหาค่าเฉลี่ยจาก 3 ค่าที่เหลือ

## 5. วิธีใช้โปรแกรมต้นแบบ

```bash
gcc timing_template.c -o timing
./timing data_1000.txt targets_1000.txt
```

บน Windows ใช้ `timing.exe data_1000.txt targets_1000.txt`

โปรแกรมจะทำสามอย่างให้อัตโนมัติ คือ อ่านไฟล์ข้อมูลและค่าที่ค้นหา ตรวจความถูกต้องของผลการค้นหาทั้ง 10 ค่า แล้วจึงวัดเวลาเฉลี่ยต่อการค้นหาหนึ่งครั้ง

**จุดที่แต่ละกลุ่มต้องแก้ไขมีเพียงจุดเดียว** คือฟังก์ชัน `MySearch()` ให้แทนที่ด้วยอัลกอริทึมการค้นหาของกลุ่มตนเอง ส่วนที่เหลือใช้ได้เลยโดยไม่ต้องแก้

## 6. ตัวอย่างผลลัพธ์อ้างอิง

ผลด้านล่างได้จากการรันบนเครื่องทดสอบหนึ่งเครื่อง ใช้เป็นแนวทางเทียบเคียงเท่านั้น **ตัวเลขบนเครื่องกลางในห้องเรียนจะต่างจากนี้** ขึ้นกับความเร็วของเครื่อง

| n | Sequential Search (ms) | Binary Search (ms) |
|---|---|---|
| 1,000 | 0.000228 | 0.000011 |
| 10,000 | 0.002148 | 0.000016 |
| 100,000 | 0.024172 | 0.000023 |

**การแปลผล** เมื่อ n เพิ่มจาก 1,000 เป็น 100,000 คือเพิ่ม 100 เท่า

- Sequential Search: เวลาเพิ่มประมาณ 106 เท่า → k = log(106) / log(100) ≈ 1.01 → **O(n)** ตรงตามทฤษฎี
- Binary Search: เวลาเพิ่มเพียงประมาณ 2.1 เท่า → k ≈ 0.16 ซึ่งใกล้ศูนย์ → **O(log n)** ตรงตามทฤษฎี

สังเกตว่า Binary Search ที่ n = 1,000 ใช้เวลาเพียง 0.000011 มิลลิวินาที ซึ่งถ้าไม่ได้วนซ้ำ 1,000 รอบจะวัดไม่ได้เลยและจะแสดงผลเป็น 0.000000 ทั้งหมด

## 7. หมายเหตุสำหรับผู้สอน

- ข้อมูลสร้างด้วยตัวสุ่มที่กำหนดค่าเริ่มต้นไว้คงที่ (seed = 20261005) จึงสร้างซ้ำให้ได้ชุดเดิมทุกครั้ง
- `answer_key.csv` ระบุตำแหน่งที่ถูกต้องของทุกค่าทั้งในไฟล์ที่ยังไม่เรียงและไฟล์ที่เรียงแล้ว ใช้ตรวจว่าโปรแกรมของแต่ละกลุ่มคืนค่าถูกต้องหรือไม่ ก่อนนำเวลาที่วัดได้ไปใช้
- ควรตรวจความถูกต้องก่อนดูเวลาเสมอ เพราะโปรแกรมที่ทำงานผิดมักเร็วกว่าโปรแกรมที่ทำงานถูก
- หากต้องการชุดข้อมูลขนาดอื่นเพิ่มเติม สามารถปรับค่าในสคริปต์สร้างข้อมูลแล้วสร้างใหม่ได้
